# Тестовое задание на стажировку

Язык: Go
БД: PostgreSQL
Контейнеризация: Docker Compose

## Бизнес-контекст

1. Администраторы создают переговорки
2. Администраторы задают расписание доступности переговорки
3. Система автоматически формирует слоты бронирования по расписанию
4. Пользователи смотрят свободные слоты, создают и отменяют брони

## Реализовано

### Админ

1. Создание переговорки: `POST /rooms/create`
2. Создание расписания (один раз): `POST /rooms/{roomId}/schedule/create`
3. Просмотр всех броней с пагинацией: `GET /bookings/list`

### Пользователь

1. Просмотр списка переговорок: `GET /rooms/list`
2. Просмотр доступных слотов по комнате и дате: `GET /rooms/{roomId}/slots/list?date=YYYY-MM-DD`
3. Создание брони: `POST /bookings/create`
4. Отмена своей брони: `POST /bookings/{bookingId}/cancel`
5. Просмотр своих броней (только будущие слоты): `GET /bookings/my`

### Авторизация и инфо

1. Тестовая авторизация по роли: `POST /dummyLogin`
2. info endpoint: `/_info`

## Бизнес-ограничения

1. Один слот может иметь только одну активную бронь
2. Для комнаты без расписания слоты не возвращаются
3. Время и даты обрабатываются в UTC
4. Admin не может создавать брони
5. Отмена брони идемпотентна
6. Нельзя создать бронь на слот в прошлом
7. `/bookings/my` возвращает только брони на будущие слоты
8. Расписание комнаты создается только один раз

## Стратегия генерации слотов

Используется ленивая генерация слотов в `GET /rooms/{roomId}/slots/list`:
1. Проверяется существование комнаты и расписания
2. Для запрошенной даты строятся 30-минутные интервалы по расписанию
3. Интервалы добавляются(если не были добавлены ранее) в таблицу `slots`
4. Возвращаются только свободные слоты

Почему выбран этот подход:
1. Проще поддержка и меньше фоновой инфраструктуры
2. Слоты имеют стабильные UUID в БД

## Структура проекта

1. `cmd/server/main.go` — запуск приложения
2. `internal/httpapi` — HTTP-слой, валидации, обработчики
3. `internal/store` — SQL-запросы к БД
4. `internal/auth` — JWT
5. `migrations` — SQL-миграция
6. `e2e_test` — end-to-end тесты сценариев

## Запуск

### Требуемый запуск по условию

```bash
docker-compose up --build
```

Сервис доступен по адресу: `http://localhost:8080`

PostgreSQL (локально):
1. host: `localhost`
2. port: `5433`
3. db: `avito`
4. user: `avito`
5. password: `avito`


## Принятые решения и допущения

1. `/register` и `/login` не реализованы
2. Поле `createConferenceLink` в запросе создания брони принимается, но фактическая интеграция с внешним сервисом не реализована
3. Для `schedule/create` требуется совпадение `roomId` в path и body
